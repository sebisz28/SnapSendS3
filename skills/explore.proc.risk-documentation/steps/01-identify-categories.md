# Step 1: Identify Risk Categories

## Objective

Analyze HLD and context to identify risks across all categories.

## Entry Criteria

- [ ] HLD available
- [ ] Context baseline available
- [ ] ADRs available (if any)
- [ ] Slug confirmed

## Actions

### 1.1 Identify Risks by Category

Analyze the HLD, context baseline, and ADRs to identify risks in:

1. **Technical Risks** - Architecture, integration, performance, technology choices
2. **Delivery Risks** - Timeline, resources, dependencies, skill gaps
3. **Operational Risks** - Support, scalability, maintenance, monitoring
4. **Security Risks** - Data protection, access control, compliance
5. **Business Risks** - Adoption, value realization, market, competition

### 1.2 Sources of Risk

- Architecture decisions (from ADRs) — trade-offs and rejected alternatives
- Assumptions (from context) — unvalidated beliefs
- Dependencies — external systems, third parties, APIs
- Technology choices — maturity, team experience, vendor lock-in
- Scope — complexity, ambiguity, unknowns

## Exit Criteria

- [ ] Risks identified across all 5 categories
- [ ] Each risk has a preliminary title and description
- [ ] Sources of risk documented
