# Step 2: Document Data Realities

## Objective

Understand what data exists, its quality, latency, ownership, gaps, and implications for UX.

## Entry Criteria

- [ ] Step 1 (System Context) complete

## Actions

### 2.1 Data Availability

For each data type, document:
- Source system, quality (High/Medium/Low)
- Latency (real-time/seconds/minutes/hours/daily)
- Ownership (team/dept), availability, access method

### 2.2 Data Quality Issues

For each issue:
- Description, affected data
- Impact on UX, workaround
- Resolution plan

### 2.3 Data Latency

Categorize data by latency:
- Real-time (< 1 second)
- Near real-time (1-60 seconds)
- Batch (hourly/daily)
- Historical (archived, retrieval time)

### 2.4 Data Ownership

- Who owns each data type
- Access process and restrictions
- SLAs for data access

### 2.5 Data Gaps

- What data doesn't exist but is needed
- Impact if missing, workarounds
- Can it be created? Timeline?

### 2.6 Implications for UX

- How data reality affects design decisions
- What designs are not possible due to data limitations

## Exit Criteria

- [ ] Data availability documented with quality and latency
- [ ] Data quality issues identified with UX impact
- [ ] Data gaps documented with workarounds
- [ ] UX implications listed
