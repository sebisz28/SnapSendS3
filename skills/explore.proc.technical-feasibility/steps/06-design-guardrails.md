# Step 6: Define Design Constraints and Guardrails

## Objective

Create clear boundaries for UX design — must constraints, should constraints, and guardrails for performance, data, interaction, accessibility, and devices.

## Entry Criteria

- [ ] Step 5 (Risks and Unknowns) complete

## Actions

### 6.1 Must Constraints (Cannot Be Violated)

For each constraint:
- Description, rationale, impact on design
- Concrete example, validation method

### 6.2 Should Constraints (Strong Preference, Can Be Challenged)

For each constraint:
- Description, rationale
- Trade-off if violated, when to challenge

### 6.3 Performance Guardrails

- Page load time, time to interactive
- API response time, animation frame rate, bundle size

### 6.4 Data Guardrails

- Max data displayed per view
- Pagination requirements and type
- Caching strategy, data freshness

### 6.5 Interaction Guardrails

- Debounce/throttle settings
- Optimistic updates (when to use/not use)
- Error recovery and loading states

### 6.6 Accessibility Guardrails

- Keyboard navigation, screen reader support
- Color contrast, touch targets

### 6.7 Device Guardrails

- Minimum screen size, touch target size
- Responsive breakpoints, image optimization

## Exit Criteria

- [ ] Must constraints defined with rationale
- [ ] Should constraints defined with trade-offs
- [ ] All guardrail categories documented
- [ ] Clear boundaries for UX designers
