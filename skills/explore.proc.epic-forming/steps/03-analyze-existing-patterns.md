# Step 3: Analyze Existing Patterns

## Objective

Review existing epic grouping patterns to understand established logic and ensure new capabilities align with current epic structure.

## Entry Criteria

- System capabilities analyzed (Step 2 complete)
- Access to existing epics in `explore/epics/`
- Capability inventory ready for pattern matching

## Actions

### 3.1 Inventory Existing Epics

Catalog current epic landscape:
- **Epic List**: All existing epics with IDs and titles
- **Epic Boundaries**: What each epic covers and excludes
- **Capability Coverage**: Which capabilities are in each epic
- **Epic Relationships**: How epics relate to each other

### 3.2 Identify Grouping Logic

Determine the established grouping patterns:
- **Primary Grouping Criteria**: Main logic (systems, clients, personas, technical domains)
- **Secondary Patterns**: Additional grouping considerations
- **Boundary Rules**: What defines epic boundaries
- **Consistency Patterns**: How similar capabilities are grouped

### 3.3 Document Epic Patterns

Create pattern documentation:
- **Grouping Logic**: Established criteria for capability grouping
- **Boundary Rules**: How epic boundaries are defined
- **Naming Conventions**: How epic names reflect grouping logic
- **Size Guidelines**: Typical epic scope and complexity

### 3.4 Assess Pattern Fit

Evaluate how well current patterns work:
- **Pattern Effectiveness**: Do current groupings make sense?
- **Boundary Clarity**: Are epic boundaries clear and logical?
- **Coverage Completeness**: Do patterns cover all capability types?
- **Consistency Quality**: Are similar capabilities grouped consistently?

## Discussion Point (Governed Mode)

**STOP**: Present pattern analysis for validation:
- "I've reviewed the existing epics and identified the following grouping patterns:"
- "Primary grouping logic: [systems/clients/personas/etc.]"
- "Current epic boundaries: [summary of how epics are organized]"
- "Pattern effectiveness: [assessment of current approach]"
- "Does this pattern analysis match your understanding of how epics should be grouped?"

## Heuristic (Delegated Mode)

If in delegated mode:
- Inventory all existing epics and their capabilities
- Identify primary grouping logic through pattern analysis
- Document epic boundaries and naming conventions
- Assess pattern effectiveness using consistency metrics
- Proceed to Step 3 with documented patterns

## Exit Criteria

- [ ] Existing epics inventoried and cataloged
- [ ] Grouping logic identified and documented
- [ ] Epic boundaries and patterns documented
- [ ] Pattern effectiveness assessed
- [ ] Ready for capability placement decisions
