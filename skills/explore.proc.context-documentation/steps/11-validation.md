# Step 11: Validation

## Objective

Run a completeness check on the context document to ensure all required sections are present and properly documented.

## Entry Criteria

- [ ] Step 10 (Write Context Document) complete
- [ ] Document exists at `explore/explore-[slug]/context.md`

## Actions

### 11.1 Run Completeness Check

Verify all required sections:

- [ ] Header complete with Signal ID, Phase, Created date, Status
- [ ] Problem statement includes reframed problem, root cause, impact, desired outcome
- [ ] Scope clearly defines In Scope, Out of Scope, and Boundary Conditions
- [ ] Domain model includes Core Entities table and Entity Relationships diagram
- [ ] System map includes Integration Architecture table and Data Flow Diagrams
- [ ] Technical constraints documented with Status (✅⚠️❌), Impact, Notes
- [ ] Stakeholder Map includes Stakeholders table and comprehensive RACI Matrix
- [ ] Governance Framework includes Decision Authority and Approval Gates
- [ ] Assumptions Catalogue includes Owner and Closes In columns
- [ ] Gaps Catalogue includes Why It Matters and Question for Stakeholder
- [ ] Context Summary (One-Page Baseline) present
- [ ] Enrichment log initialized with SP1 completion entry
- [ ] Footer includes Last Updated and Updated By

### 11.2 Present Validation Results

```
Context Documentation Complete

File: explore/explore-[slug]/context.md
Entities: [N] identified
Systems: [N] mapped
Stakeholders: [N] identified
Assumptions: [N] catalogued
Gaps: [N] identified

Validation: [N] of [N] checks passed ✓

Ready for Persona and Journey Mapping.
```

## Exit Criteria

- [ ] All 13 completeness checks pass
- [ ] Validation results presented to human
- [ ] Context document ready for downstream use
