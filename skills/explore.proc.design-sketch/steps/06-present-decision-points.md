# Step 6: Present Architectural Decision Points

For each decision that needs to be made, present options with tradeoffs. Do NOT pre-select. Reference relevant patterns from the architectural pattern library (persistent knowledge) when available.

```
Architectural Decision Points

Decision [N]: [Title]

Context: [Why this decision matters]
Pattern library reference: [Pattern name from library, if applicable]

| Option | Description | Pros | Cons | NFR Impact | Evidence |
|--------|------------|------|------|-----------|----------|
| A | [Description] | [Advantages] | [Disadvantages] | [Impact on quality attributes] | [VALIDATED] / [ASSUMPTION] |
| B | [Description] | [Advantages] | [Disadvantages] | [Impact on quality attributes] | [VALIDATED] / [ASSUMPTION] |
| C | [Description] | [Advantages] | [Disadvantages] | [Impact on quality attributes] | [VALIDATED] / [ASSUMPTION] |

Agent recommendation: [If clear tradeoff winner, state it. Otherwise: "Architect to decide — tradeoffs are balanced."]

[Repeat for each decision point]

Total decision points: [N]
Agent has recommendation: [N]
Architect must decide: [N]

For each decision point, please select an option:
- Select options — I'll specify my choice for each decision
- Need more analysis — tell me which decision needs deeper exploration
- Defer some — tell me which decisions to carry as open questions
```

**STOP**: Wait for architect to select options for each decision point.
