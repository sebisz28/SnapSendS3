# Step 10: Define Checkpoints

## Objective

Set validation points with specific criteria aligned to phase boundaries.

## Entry Criteria

- [ ] Step 9 (Constraints) complete with constraints documented

## Actions

### 10.1 Define Milestone Checkpoints

Create checkpoint schedule:

```
Checkpoints

| Milestone | Criteria |
|-----------|---------|
| Week 1 end | Stakeholder map complete (A1); Context baseline validated (A2); Personas created (A3); Current-state journeys mapped (A4); Hypothesis drafted and validated (A5) |
| Week 2 end | HLD created and approved (A6); ADRs documented (A7); Future-state journeys updated (A8); User flows created (A9) |
| Week 3 end | Risk register complete (A10); All Phase 2 artifacts validated by stakeholders |
| Week 4 end | PRD drafted and approved (A11); Consistency check passed (A12); Epics formed (A13); Govern readiness confirmed (A14) |

Note: 
- Each checkpoint lists completed activities with their A# codes
- Checkpoints align with phase boundaries
- Criteria should be specific and measurable
- Adjust timeline based on project complexity
```

## Exit Criteria

- [ ] Checkpoints defined for each phase boundary
- [ ] Each checkpoint has specific, measurable criteria
- [ ] Activity codes referenced in criteria
