# Step 5: Map User Roles and Responsibilities

## Objective

Define domain roles (not org chart) based on responsibilities, permissions, and typical tasks.

## Entry Criteria

- [ ] Step 4 (Domain Rules) complete

## Actions

### 5.1 Define Roles

**For each role, document**:
- **Role name**: [Name]
- **Description**: [What this role represents in the domain]
- **Responsibilities**: [What this role is responsible for]
- **Permissions**: [What this role can do]
- **Constraints**: [What this role cannot do]
- **Typical tasks**: [Common workflows for this role]

### 5.2 Categorize Roles

**Role categories**:
1. **Primary users**: Roles that are core to the domain
2. **Secondary users**: Supporting roles
3. **Administrative roles**: Management and oversight
4. **System roles**: Automated or system-level actors

### 5.3 Map Role Relationships

- [Role 1] → [Role 2]: [How they interact]
- [Role 1] delegates to [Role 2]: [What is delegated]

### 5.4 Create Permission Matrix

| Role | Entity | Create | Read | Update | Delete | Special Actions |
|------|--------|--------|------|--------|--------|-----------------|
| [Role 1] | [Entity] | ✅ | ✅ | ✅ | ❌ | [Action] |

This is about domain roles, not job titles or org structure.

## Exit Criteria

- [ ] All domain roles defined with responsibilities
- [ ] Roles categorized by type
- [ ] Role relationships mapped
- [ ] Permission matrix created
