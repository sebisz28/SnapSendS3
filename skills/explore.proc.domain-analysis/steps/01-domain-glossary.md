# Step 1: Define Domain Glossary

## Objective

Create shared vocabulary for consistent communication across all artifacts.

## Entry Criteria

- [ ] Context baseline available (problem statement, scope)
- [ ] Signal document available
- [ ] Slug confirmed

## Actions

### 1.1 Extract Domain Terms

Extract terms from Signal, Context, and stakeholder conversations:

**Process**:
1. Extract terms from Signal, Context, and stakeholder conversations
2. Define each term clearly and unambiguously
3. Identify synonyms and clarify preferred term
4. Note any terms that mean different things in different contexts

**For each term, document**:
- **Term**: [Official name]
- **Definition**: [Clear, unambiguous definition]
- **Synonyms**: [Alternative terms to avoid]
- **Context**: [When/where this term is used]
- **Examples**: [Concrete examples]

### 1.2 Categorize Terms

**Categories to cover**:
- Core domain entities (nouns)
- Domain actions (verbs)
- States and statuses
- Roles and actors
- Business concepts
- Technical terms with domain-specific meaning

### 1.3 Human Checkpoint

Present glossary draft and ask:
- Do you have existing glossaries or terminology standards I should reference?
- Are any terms missing or incorrectly defined?

**STOP**: Wait for human to provide any existing glossaries or confirm to proceed.

## Exit Criteria

- [ ] All domain-specific terms identified and defined
- [ ] Synonyms documented with preferred terms clarified
- [ ] Terms categorized by type
- [ ] Human has reviewed and approved glossary
