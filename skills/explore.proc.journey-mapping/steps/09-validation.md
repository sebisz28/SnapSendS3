# Step 9: Validation

## Objective

Run a completeness check on the journey map document.

## Entry Criteria

- [ ] Journey map exists at `explore/domain/journey-[slug].md`

## Actions

### 9.1 Current-State Validation

- [ ] All stages have current-state documented
- [ ] Actions, thoughts, feelings documented per stage
- [ ] Pain points identified with impact levels
- [ ] Touchpoints mapped
- [ ] Validation status tagged ([VALIDATED] or [ASSUMPTION])

### 9.2 Future-State Validation (if Part B complete)

- [ ] All stages have future-state documented
- [ ] Future-state addresses identified pain points
- [ ] Opportunities linked to future-state improvements
- [ ] New touchpoints specified

### 9.3 Calculate Validation Priority

- **High** = >50% of steps are assumptions (needs immediate validation)
- **Medium** = 25-50% of steps are assumptions (validate before design decisions)
- **Low** = <25% of steps are assumptions (well-validated, safe to use)

### 9.4 Present Validation Results

```
Journey Map Complete

File: explore/domain/journey-[slug].md
Primary Actor: [Persona name]
Stages: [N] stages mapped
Pain Points: [N] identified
Opportunities: [N] identified
Validation Priority: [High/Medium/Low]

Current-state: Complete ✓
Future-state: [Complete ✓ / Pending (will be added in Solution Design)]

Ready for use in Hypothesis Documentation and PRD Generation.
```

## Exit Criteria

- [ ] All completeness checks pass
- [ ] Validation priority calculated
- [ ] Validation results presented to human
- [ ] Document ready for downstream consumption
